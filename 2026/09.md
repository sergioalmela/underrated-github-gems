## 🏆 Top 3 Picks

### 🥇 #1 - Tessera
**Repo:** [`MaxGramser/homeassistant_espscreen`](https://github.com/MaxGramser/homeassistant_espscreen)  
**Language:** Python  
**Why it stands out:** Makes affordable ESP32 touch panels into configurable Home Assistant controls. A visual manager handles layouts and updates, reducing the amount of device-specific YAML users need to maintain. The documentation describes supported panels and tile capabilities, with lighting, climate, media, and other controls arranged for each screen size.

**Highlights:**

- Drag-and-drop tile layout inside Home Assistant
- Supported ESP32 panels from 2.8 to 10.1 inches
- USB setup and Wi-Fi updates
- Multi-page controls, status displays, and automation-driven alerts

---

### 🥈 #2 - ddc
**Repo:** [`ejfkdev/ddc`](https://github.com/ejfkdev/ddc)  
**Language:** Rust  
**Why it stands out:** A Rust decompiler for Android DEX bytecode that also supports a query-first investigation workflow. Developers can inspect strings, references, classes, manifests, and resources before deciding to decompile an entire package. Its reproducible-output approach and documented validation corpus make it worth examining without needing to accept benchmark numbers as universal guarantees.

**Highlights:**

- DEX-to-Java decompilation and per-method inspection
- Multi-dex APKs and XAPK/APKS/APKM containers
- Queries for strings, references, hierarchies, and resources
- Documented validation and known limitations

---

### 🥉 #3 - BG0
**Repo:** [`opencoredev/bg0`](https://github.com/opencoredev/bg0)  
**Language:** TypeScript  
**Why it stands out:** Removes image backgrounds in the browser without uploading the source image for inference. It selects WebGPU when available and otherwise uses WebAssembly, then exports a transparent PNG. A reusable browser package exposes the same workflow to other applications; the model is downloaded and cached locally, with its own license terms.

**Highlights:**

- WebGPU inference with a WebAssembly fallback
- Local image processing and transparent PNG export
- Pinned model download and browser-side caching
- Reusable package for progress, cancellation, and output handling

## 🔖 Honorable Mentions

### tool-journal
**Repo:** [`RaycarlLei/tool-journal`](https://github.com/RaycarlLei/tool-journal)  
**Language:** TypeScript  
**Why it stands out:** A TypeScript/SQLite execution journal for tools retried after crashes. It records intent, coordinates leases, and represents uncertain outcomes explicitly. Its recovery demos explain why a journal alone cannot guarantee a single external effect: automatic retry still needs downstream idempotency and a bounded admission window.

---

### Rooms
**Repo:** [`saragordic/rooms`](https://github.com/saragordic/rooms)  
**Language:** Swift  
**Why it stands out:** A native Mac utility that groups windows by project and restores their layout through a keyboard launcher. Other windows are hidden or parked, while recovery records support restoring them after quitting or a crash. It works locally and requires Accessibility permission to move windows.
